# Cloud deployment (AWS / GCP)

End-to-end, cloud-first deployment of Forge CI. Two paths:

1. **Terraform / OpenTofu** (`deploy/terraform`) — provisions a Kubernetes
   cluster, a managed Postgres, an object-storage artifact bucket, a generated
   secret, and installs the Helm chart. One `apply` stands up the whole
   platform on AWS (EKS + RDS + S3) or GCP (GKE + Cloud SQL + GCS).
2. **Bring-your-own cluster** — you already have a cluster and a DB; install the
   Helm chart directly (skip to [BYO cluster](#byo-cluster-helm-only)).

The Helm chart is the single deployable unit; Terraform simply feeds it
cloud-derived values (DB URL, bucket + keys, generated `FORGE_SECRET_KEY`).

## What Terraform creates

| Aspect | AWS (`deploy/terraform/aws`) | GCP (`deploy/terraform/gcp`) |
|---|---|---|
| Network | VPC, public/private subnets, IGW, NAT | VPC, subnet w/ pod+service ranges, Cloud NAT, PSA range |
| Cluster | EKS + managed node group | GKE (VPC-native) + node pool |
| Database | RDS Postgres → `DATABASE_URL` | Cloud SQL Postgres (private IP) → `DATABASE_URL` |
| Artifacts | S3 bucket + least-priv IAM user + access key | GCS bucket + service account + HMAC key (S3-interop) |
| Secret | Secrets Manager (`FORGE_SECRET_KEY`, runner token) | Secret Manager (same) |
| App | `helm_release` of `deploy/helm/forge-ci` | same |

The artifact modules output `S3_ENDPOINT`/`S3_BUCKET`/`S3_REGION`/
`S3_ACCESS_KEY`/`S3_SECRET_KEY`, exactly what `internal/blob` consumes — on GCP
via the interoperability endpoint `storage.googleapis.com`.

## Module layout

```
deploy/terraform/
  modules/
    forge-release/     # kubernetes Secret + helm_release (provider-agnostic)
    aws-network/  aws-eks/  aws-rds/  aws-artifacts/  aws-secret/
    gcp-network/  gcp-gke/  gcp-cloudsql/ gcp-artifacts/ gcp-secret/
  aws/               # root env: wires the aws-* modules + forge-release
  gcp/               # root env: wires the gcp-* modules + forge-release
```

## Prerequisites

- OpenTofu ≥ 1.6 (or Terraform ≥ 1.6), Helm 3+, `kubectl`.
- Cloud CLI auth in your shell:
  - AWS: `aws sso login` / env creds, with rights to create EKS/VPC/RDS/S3/IAM.
  - GCP: `gcloud auth application-default login`, project APIs enabled
    (`container`, `sqladmin`, `servicenetworking`, `secretmanager`, `storage`).
- Container images built and pushed to your registry (ECR / Artifact Registry) —
  see the chart README's "Prerequisites". Set `image_registry` accordingly.
- A DNS hostname you control for `domain` (point it at the ingress LB after apply).

## AWS — step by step

```sh
cd deploy/terraform/aws
cp terraform.tfvars.example terraform.tfvars   # edit: region, domain, bucket, registry
export TF_VAR_webhook_secret="…"               # optional; keep secrets out of files

tofu init
tofu plan
tofu apply
```

What happens: VPC + EKS come up, RDS Postgres is created in the private subnets,
an S3 bucket + scoped IAM user is provisioned, `FORGE_SECRET_KEY` + a runner
token are generated into Secrets Manager, and the chart is installed with
`postgresql.enabled=false`, `artifacts.store=s3`, `runner.mode=kubernetes`,
`RUNNER_AUTH=on`, and `secrets.existingSecret` pointing at a Kubernetes Secret
that Terraform populated from the cloud outputs.

Outputs:

```sh
tofu output app_url          # https://<domain>
tofu output database_endpoint
tofu output artifacts_bucket
```

Point `domain`'s DNS at the ALB the ingress created:

```sh
kubectl -n forge-ci get ingress
```

## GCP — step by step

```sh
cd deploy/terraform/gcp
cp terraform.tfvars.example terraform.tfvars   # edit: project_id, region, domain, bucket, registry
export TF_VAR_webhook_secret="…"               # optional

tofu init
tofu plan
tofu apply
```

VPC (with pod/service secondary ranges + Private Service Access), a VPC-native
GKE cluster, a private-IP Cloud SQL Postgres, a GCS bucket with an HMAC key for
S3-interop, and Secret Manager entries are created, then the chart is installed
the same way as AWS. `tofu output app_url` gives the URL; point DNS at the GCE
ingress address.

## How the pieces are wired

- **Database** — the RDS/Cloud SQL module emits a full DSN
  (`postgres://user:pass@host:5432/forge?sslmode=…`) that flows into the
  `forge-release` module and is stored in a Kubernetes Secret as `DATABASE_URL`.
  The chart runs with `postgresql.enabled=false`.
- **Artifacts** — bucket + credentials become `config.artifacts.s3.*` (endpoint,
  bucket, region, access key) plus `S3_SECRET_KEY` in the Secret.
- **Secrets** — `FORGE_SECRET_KEY` (base64 32-byte AES key) and the runner
  token are generated by Terraform, kept in the cloud secret manager for
  durability, and mirrored into the in-cluster Secret the chart reads via
  `secrets.existingSecret`.
- **SSO** — set `admin_emails`; configure an SSO provider in the dashboard after
  first login (see [sso.md](sso.md)). `EXTERNAL_URL`/`FRONTEND_URL` are derived
  from `domain`.
- **Ingress / LB** — `ingress_class_name` selects the controller (`alb` on AWS,
  `gce` on GCP); `/api` routes to the server, `/` to the dashboard. Provide TLS
  via the class's annotations (ACM on ALB, managed certs on GCE) or cert-manager.
- **Runners** — `runner.mode=kubernetes` runs one manager that spawns ephemeral
  job pods with the namespaced RBAC from
  [kubernetes-deployment.md](kubernetes-deployment.md).

## Corner cases / toggles

Set these in `terraform.tfvars`:

- **Bring-your-own cluster** — `create_cluster=false` and supply
  `byo_cluster_endpoint` / `byo_cluster_ca_certificate` / `byo_cluster_token`.
- **Bring-your-own VPC** — `create_vpc=false` and supply the subnet ids (AWS) or
  network/subnet/range names + PSA connection (GCP).
- **In-cluster Postgres instead of managed** — skip the DB module and install the
  chart with `postgresql.enabled=true` (BYO Helm path below); the Terraform roots
  default to a managed DB.
- **Runner auth** — `runner_auth=on` (default) makes the secret module generate a
  token and wires `RUNNER_AUTH=on`; `off` disables both.
- **Region/project validation** — `region` (both) and `project_id` (GCP) are
  required and validated as non-empty; `artifacts_bucket_name` is required.

## BYO cluster (Helm only)

Already have a cluster + DB? Skip Terraform:

```sh
helm dependency build deploy/helm/forge-ci
helm install forge ./deploy/helm/forge-ci -n forge-ci --create-namespace \
  -f deploy/helm/forge-ci/values-prod.yaml \
  --set image.registry=<registry> \
  --set postgresql.enabled=true              # or point database.url at your DB
```

For a managed DB, keep `postgresql.enabled=false` and provide `database.url`
(or an `existingSecret` carrying `DATABASE_URL`). Full chart docs:
[deploy/helm/forge-ci/README.md](../deploy/helm/forge-ci/README.md).

## Teardown

```sh
cd deploy/terraform/aws   # or gcp
tofu destroy
```

Notes:

- RDS/Cloud SQL and GKE default to **deletion protection on**. To tear down a
  non-prod stack set `db_deletion_protection=false`,
  `cluster_deletion_protection=false` (GCP), and `db_skip_final_snapshot=true`
  (AWS) before `destroy`.
- Object buckets with data won't delete unless `artifacts_force_destroy=true`.
- Secrets Manager / Secret Manager entries use a recovery window; they linger
  (recoverable) after destroy by design.

## Verification note

The Terraform here was verified statically only — `tofu fmt -recursive` and
`tofu init -backend=false` + `tofu validate` in both `aws/` and `gcp/`. It was
**not** applied against real cloud accounts. Run `tofu plan` in your own account
before `apply` and review the resource set.
